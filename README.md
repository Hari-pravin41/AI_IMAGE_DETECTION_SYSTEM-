# AI Image Detection System

AI Image Detection System is a local Flask application for AI-assisted visual image assessment,
SQLite analysis history, and ReportLab PDF reports. Active image analysis uses a vision service
configured through the backend environment. Previously trained local model files remain on disk but
are not loaded by active web analysis.

## Technology

- Python 3.10+
- Flask
- Official image-analysis Python SDK
- python-dotenv
- SQLite
- ReportLab
- HTML, CSS, and JavaScript frontend

## Setup

```powershell
cd C:\Users\harip\Music\AI_ML\ai-image-detector
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
```

Configure `.env` with:

```text
GEMINI_API_KEY=your_backend_key
GEMINI_MODEL=gemini-3-flash-preview
ANALYSIS_RATE_LIMIT=10
ANALYSIS_RATE_WINDOW_SECONDS=3600
```

Keep `GEMINI_API_KEY` only in `.env`. `.env` is excluded from Git. Do not configure secrets in
frontend environment variables. The selected model can also be discovered automatically when
`GEMINI_MODEL` is blank.

### Password recovery

Password recovery emails use SMTP configured only in the backend `.env`:

```text
APP_BASE_URL=http://127.0.0.1:8000
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USE_TLS=true
SMTP_USERNAME=your-smtp-user
SMTP_PASSWORD=your-smtp-password
SMTP_FROM=account@example.com
```

Reset links expire after 30 minutes and work once. Recovery responses do not reveal whether an
email address is registered. For local development only, `PASSWORD_RESET_DEV_LINKS=true` prints
generated reset links to the server console; never enable this setting on a shared or public server.

## Run

The legacy `--model` argument is retained for command compatibility, but active web analysis does
not load or call it.

```powershell
.\.venv\Scripts\python.exe -m aidetect serve --model models\openfake_ood_v1 --host 127.0.0.1 --port 8000
```

Open http://127.0.0.1:8000.

## Workflow

Upload a JPG, PNG, or WEBP image up to 10 MB, preview it, and select **Analyze Image**. The
browser sends the image to Flask, and Flask sends the actual image bytes to the configured backend
vision service. The structured result is saved in SQLite and displayed in the interface.

## API

- `GET /api/health`
- `POST /api/analyze-image`
- `GET /api/history`
- `GET /api/history/<analysis_id>`
- `DELETE /api/history/<analysis_id>`
- `GET /api/reports/<analysis_id>/pdf`

Example:

```powershell
curl.exe -F "image=@photo.jpg" http://127.0.0.1:8000/api/analyze-image
```

## History and reports

Analysis records and original image bytes are stored in `data/analysis_history.db`. PDF reports are
generated by the backend from the saved analysis and include the filename, report ID, assessment,
description, observations, explanation, limitations, image preview, and disclaimer.

## Safety and limitations

Visual analysis is not definitive forensic proof of image origin. The current service is a
general-purpose vision model rather than a scientifically validated detector. The application does
not report invented accuracy, calibrated confidence, source metadata, or forensic certainty.
Results must not be used as the sole basis for consequential decisions.

## Product safety controls

- Uploads are checked as real, decodable images before analysis.
- API credentials remain only in the backend `.env` configuration.
- Per-IP analysis requests can be limited with `ANALYSIS_RATE_LIMIT` and
  `ANALYSIS_RATE_WINDOW_SECONDS`.
- Reports distinguish verified file facts from AI-assisted visual interpretation.
- SHA-256 hashes identify the stored bytes but do not establish image origin.
- EXIF observations are sanitized and exclude location/GPS fields.
- C2PA-style markers are reported as unverified unless cryptographic validation is explicitly implemented.
- No result should be treated as definitive forensic proof.
